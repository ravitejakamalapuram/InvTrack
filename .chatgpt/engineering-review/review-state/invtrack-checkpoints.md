## Validated operational lessons

- **Pattern:** CodeRabbit did not automatically review InvTrack PRs #950/#952 when they were marked ready, and explicit `@coderabbitai review` requests were rate-limited. **Why the assumption failed:** the bot explicitly says automatic reviews are disabled for this repository because it has fewer than 10 stars; ready status is not a review. **Evidence:** bot skip-review comments on #950/#952 (2026-10-09 15:24:56Z and 15:34:35Z) and rate-limit responses at 16:32:54Z and 16:33:07Z. **Improved heuristic:** require an explicit completed bot review or actionable findings; never infer review completion from PR readiness or CI status. When the bot explicitly says automatic reviews are disabled because the repository has fewer than 10 stars, use a manual trigger; treat rate-limit responses as failed requests, not reviews. **Confidence:** high.

- **Pattern:** Integration tests that mount `InvTrackerApp` directly bypass `main()` and therefore bypass Firebase initialization. A root startup initializer can activate Firebase-backed providers when tests fake a signed-in user; one setup error then cascades across unrelated UI tests. **Why it was missed:** existing test app helpers mocked repositories/services but did not account for newly added root startup providers. **Evidence:** nightly run `37901616478` reports `[core/no-app] No Firebase App '[DEFAULT]'`; `integration_test/app_test.dart` directly pumps `InvTrackerApp` and does not initialize Firebase or override the currency-cache provider, while production `main.dart` initializes Firebase before `runApp`. **Improved heuristic:** whenever root startup providers change, audit all test app factories and provider overrides; explicitly initialize Firebase or override Firebase-backed startup services, and distinguish the first causal error from downstream test-binding failures. **Confidence:** high.

- **External-review reconciliation (#934 / v3.75.2):** Rechecked CodeRabbit's earlier findings against release commit `204e9f438e933f5fc4e3e9bc353212dd98da1c97`. ## Checkpoint discipline

- Skip a PR when its head SHA, diff, discussion/review state, requested changes, external findings, and relevant CI evidence are unchanged.
- When any material input changes, review the delta first and reassess affected prior findings.
- Store only durable conclusions and identifiers needed to resume review. Record tests as executed only when the workflow/run proves they executed.
